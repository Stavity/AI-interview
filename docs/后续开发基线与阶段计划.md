# 后续开发基线与阶段计划

> 基线日期：2026-10-08
> 目标数据库：`interview_guide_redesign`
> 用途：作为后续开发、验收和提交拆分的唯一执行基线；历史讨论与本文件冲突时，以本文件和当前代码为准。

## 1. 当前有效产品范围

当前产品主线只有以下四部分：

1. 公开用户注册、邮箱验证、登录、退出和密码找回。
2. 简历、普通文本面试、语音面试、知识库、聊天和学习数据的用户归属与隔离。
3. 题目知识标签体系，以及出题时供模型查询合法标签的工具。
4. 面试结果驱动的学习证据、学习进度和个性化学习路线。

多轮面试不属于当前产品范围，也不属于后续开发计划。除非产品重新立项，否则不再围绕它设计接口、表、页面、迁移、测试或提交任务。Git 工作树中已删除文件的状态只是尚未提交的历史工作记录，不代表该功能仍存在或需要继续开发。

注意：数据库备份和迁移是部署操作，不以“代码已提交”代替运行验收；执行前必须明确停写窗口。

### 阶段 C：面试结果沉淀为学习证据

状态：进行中。文本面试证据表、幂等插入和评估成功后的事务内写入已编码并通过全量测试；`V20261008` 已由 Flyway 正式应用到目标数据库，重复插入验收通过且无测试数据残留。语音面试适配待后续小阶段完成。

目标：建立可追溯、幂等的“题目标签 → 答题评估 → 学习证据”链路。

工作项：

- 固化评估输出中的题目 ID、标签版本、知识点标签、得分、置信度和评价时间。
- 增加用户学习证据表，记录来源面试、答案、题目、标签和评估版本。
- 以 `owner + answer/evaluation + tag` 建立幂等约束，重试不能重复累计。
- 仅接受题目当次出题时冻结的有效标签，避免标签目录变化篡改历史证据。
- 补齐异步评估成功、失败、重试和重复消费测试。

完成标准：每条进度变化都能追溯到具体用户、面试、题目、答案和标签；重复评估不重复计分，失败不会产生半条证据。

建议提交：`feat: persist tagged learning evidence from interview evaluations`

### 阶段 D：学习进度聚合

目标：把原始证据稳定聚合成用户在知识树各节点上的掌握状态。

工作项：

- 定义进度指标：掌握度、证据数量、最近练习时间、连续正确/错误、置信度和衰减规则。
- 明确多叉树父节点聚合算法，叶子证据不能简单重复累计到所有祖先。
- 增加可重算的聚合任务；规则升级后可由证据重新生成进度。
- 提供用户进度查询接口和前端知识树视图。

完成标准：同一组证据重复聚合结果一致；规则可版本化；用户只能看到自己的进度。

建议提交：`feat: aggregate user mastery across the knowledge tree`

### 阶段 E：个性化学习路线

目标：根据用户目标、掌握度和知识依赖生成并持续更新学习路线。

工作项：

- 先用确定性规则选出薄弱且满足前置依赖的知识点，再让模型负责解释、编排和推荐内容。
- 保存路线版本、生成依据和触发原因，避免模型直接覆盖历史路线。
- 定义更新触发：面试完成、阶段任务完成、进度显著变化或用户主动刷新。
- 路线任务关联知识标签、题目难度、资源来源和完成状态。
- 增加冷启动、证据不足、标签失效和模型失败的降级策略。

完成标准：路线中的每项建议都能解释“为什么推荐”；新面试证据可以幂等更新路线；模型失败时仍能返回规则生成的基础路线。

建议提交：`feat: generate explainable personalized learning paths`

### 阶段 F：账号运营闭环

目标：补齐真实部署所需的账号管理能力。

工作项：

- SMTP 真实环境验收和告警。
- 初始管理员安全引导。
- 用户禁用、会话撤销、数据保留和异步删除流程。
- 注册、验证、找回密码和敏感操作审计。

完成标准：管理员不由公开注册产生；禁用账号立即失去访问能力；删除任务可重试、可审计且不会误删其他用户数据。

建议提交：`feat: complete account administration lifecycle`

## 4. 固定的数据链路

后续开发必须始终围绕以下链路验证，不得只增加字段或页面：

```text
题目知识树与合法标签
        ↓ 出题时冻结标签快照
用户完成面试题
        ↓ 结构化评估
带来源与版本的学习证据
        ↓ 幂等聚合
用户知识点掌握进度
        ↓ 规则筛选 + 模型编排
可解释的个性化学习路线
        ↓ 后续练习/面试产生新证据
持续更新
```

其中，用户身份和 `owner_user_id` 贯穿整条链路；任何异步任务、向量检索、文件访问和 WebSocket 都不能绕开该归属。

## 5. 上下文边界

后续任务默认采用以下规则：

- 只讨论普通文本面试和语音面试；已退出产品范围的历史功能不作为设计依据。
- “认证闭环”只表示注册登录可用，不等于业务数据隔离已经验收。
- “学习进度已隔离”不等于“面试结果自动更新学习进度”已经实现。
- 前端声明了 API 不代表后端链路存在；必须核对控制器、服务、持久化和实际运行结果。
- 代码中存在迁移脚本不代表目标数据库已经迁移；以 Flyway 历史和运行验收为准。
- 当前数据库盘点值会变化；每次迁移前必须重新读取，不能依赖旧数字。
- 每个阶段独立提交；提交前按文件清单精确暂存并检查 staged diff。
- 不清库、不删除 RustFS 对象、不清空 Redis，不用手工 DDL 跳过 Flyway。
