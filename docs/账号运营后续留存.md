# 账号运营后续留存

> 状态：暂缓，不阻塞当前“面试 → 学习证据 → 掌握度 → 个性化学习路线”主链路。
> 恢复条件：产品进入真实公开运营、需要管理员处理用户，或需要执行账户删除请求时再立项。

## 当前已具备

- 公开注册、邮箱验证、登录、登出、当前登录用户、重发验证邮件、忘记密码和重置密码。
- 账号状态 `PENDING_EMAIL_VERIFICATION`、`ACTIVE`、`DISABLED`，以及 `USER`、`ADMIN` 角色模型。
- BCrypt 密码哈希；验证/重置令牌使用安全随机值，仅保存 SHA-256 摘要，具备过期与一次性消费约束。
- Spring Session JDBC 会话存储；登录轮换 Session ID，登出清除会话；重置密码会撤销该账号全部已有会话。
- SMTP 配置与邮件模板已接入，但默认关闭，等待真实环境验收。

## 暂缓事项

### F1：管理员与账号禁用

- 设计安全的首个管理员创建/恢复流程；公开注册不得自行获得 `ADMIN`。
- 提供管理员查看用户、禁用与恢复接口及页面。
- 禁用账号时立即撤销其所有 Spring Session，并拒绝后续认证请求。
- 为管理员操作记录操作者、目标账号、原因、时间与结果。

### F2：真实 SMTP 验收

- 配置真实 SMTP，开启 `APP_AUTH_MAIL_ENABLED`。
- 端到端验证注册邮件、验证链接、密码重置邮件、过期/重放链接及重置后的会话撤销。
- 记录邮件投递失败，并提供可观测告警。

### F3：删除与审计闭环

- 定义用户删除申请、保留期、取消窗口和管理员审批策略。
- 以可重试的异步任务删除用户私有数据库记录、RustFS 对象、向量数据和会话。
- 删除任务必须按 `owner_user_id` 限定范围，保留审计轨迹，且失败不能影响其他用户数据。
- 建立注册、验证、重置密码、禁用、恢复和删除的敏感操作审计表与查询能力。

## 恢复开发顺序

先完成 F1，再做 F2，最后做 F3。原因是管理员权限和即时会话撤销是邮件运营、删除审批与异常处理的安全前提。

## 约束

- 不在数据库迁移或代码中写入默认管理员密码。
- 不以公开注册接口赋予 `ADMIN`。
- 不通过手工 SQL、清库或绕过 Flyway 的方式处理账户数据。
- 用户删除必须先完成可恢复备份、范围核对和审计设计，再执行实际清理。
